Three things move, one at a time

Pick a piece and see what changes

Your MERN app has three separate parts. Each one "goes live" in its own way. Click a tab.

Local MongoDB → MongoDB Atlas

Right now your data lives in a database only your laptop can see. Atlas is the same MongoDB, just hosted by someone else, reachable from anywhere.

// on your laptop mongodb://localhost:27017/mydb
// on atlas mongodb+srv://user:pass@cluster0.mongodb.net/mydb
! Data on your laptop doesn't teleport to Atlas — you have to export it and import it, or start fresh.
! Atlas needs to know which computers are "allowed in" — this is called an IP whitelist.
! The password in that connection string is a secret. It never gets typed directly into your code.

Node/Express → Render (Web Service)

Your Express server currently only runs when you type npm run dev. Render keeps a copy of it running all the time, on a real address.

// on your laptop http://localhost:5000/api/tasks
// on render https://taskapp-api.onrender.com/api/tasks
! Render needs to be told two things: how to build your app, and how to start it.
! Your Atlas connection string goes into Render as an environment variable — never into your code.
! On the free plan, the server falls asleep when nobody uses it, so the first visit after a break feels slow. That's normal.

React → a static site (Render, Vercel, or Netlify)

React doesn't need a server of its own. You "build" it into plain HTML/CSS/JS files, and a static host just hands those files to visitors.

// on your laptop npm run dev → localhost:5173
// live npm run build → taskapp.onrender.com
! The live React app must be told the live backend address — not localhost.
! Refreshing a page like /dashboard can 404 unless the host is told to redirect all routes back to your app.
! If the backend blocks your frontend's address, that's a CORS error — it's the backend saying "I don't recognize you."
